# บทที่ 5
# สรุปผล อภิปรายผล และข้อเสนอแนะ

## 5.1 สรุปผลการวิจัย

การวิจัยเรื่อง การพัฒนาเว็บแอปพลิเคชันเพื่อการบริหารจัดการและตรวจสอบผลการดำเนินกิจกรรมนักศึกษา มหาวิทยาลัยราชภัฏสุรินทร์ มีวัตถุประสงค์ 3 ประการ สรุปผลได้ดังนี้

**5.1.1 ผลการออกแบบและพัฒนาระบบ**

ผู้วิจัยได้ออกแบบและพัฒนาระบบเว็บแอปพลิเคชันสำเร็จตามวัตถุประสงค์ข้อที่ 1 โดยระบบสามารถรองรับการเช็คชื่อเข้าร่วมกิจกรรมผ่าน QR Code ร่วมกับ GPS และเซลฟียืนยันตัวตน การบันทึกและคำนวณชั่วโมงกิจกรรมนักศึกษาแยกตามประเภทนักศึกษา (ภาคปกติ/ภาคพิเศษ) การเทียบโอนชั่วโมงกิจกรรมทั้งจากตำแหน่งในองค์กรนักศึกษาและกิจกรรมภายนอกมหาวิทยาลัย ตลอดจนระบบรายงานสำหรับผู้บริหารและผู้รับผิดชอบกิจกรรม พัฒนาด้วยภาษา PHP ร่วมกับเฟรมเวิร์ก Laravel บนสถาปัตยกรรม MVC และฐานข้อมูล MySQL ระบบได้ทดลองใช้งานจริงบนเซิร์ฟเวอร์ (Railway) สามารถเข้าถึงได้ทั้งบนคอมพิวเตอร์และโทรศัพท์มือถือ

**5.1.2 ผลการประเมินประสิทธิภาพของระบบ**

> **หมายเหตุสำหรับผู้วิจัย:** แทนที่ย่อหน้าด้านล่างด้วยข้อความจริงหลังกรอกตารางที่ 18 (บทที่ 4) เสร็จแล้ว — เป็นประโยคตัวอย่างที่ใช้แทนตัวเลขได้เลย เพียงเติมค่าในช่องว่าง

ผลการประเมินประสิทธิภาพของระบบโดยผู้เชี่ยวชาญด้านคอมพิวเตอร์และเทคโนโลยีสารสนเทศ จำนวน 5 ท่าน (ตารางที่ 18) พบว่าภาพรวมมีประสิทธิภาพอยู่ในระดับ **[ระบุระดับ เช่น มากที่สุด]** ค่าเฉลี่ยเท่ากับ **[X.XX]** ส่วนเบี่ยงเบนมาตรฐานเท่ากับ **[X.XX]** เมื่อพิจารณาเป็นรายด้าน พบว่าด้านที่มีค่าเฉลี่ยสูงสุดคือ **[ระบุด้าน]** (ค่าเฉลี่ย **[X.XX]**) รองลงมาคือ **[ระบุด้าน]** (ค่าเฉลี่ย **[X.XX]**) ส่วนด้านที่มีค่าเฉลี่ยต่ำที่สุดคือ **[ระบุด้าน]** (ค่าเฉลี่ย **[X.XX]**) ซึ่งสอดคล้องกับวัตถุประสงค์ข้อที่ 2 ของการวิจัย

**5.1.3 ผลการประเมินความพึงพอใจของผู้ใช้งาน**

> **หมายเหตุสำหรับผู้วิจัย:** แทนที่ย่อหน้าด้านล่างด้วยข้อความจริงหลังกรอกตารางที่ 19 (บทที่ 4) เสร็จแล้ว

ผลการประเมินความพึงพอใจของกลุ่มตัวอย่างผู้ใช้งาน จำนวน 28 คน (ตารางที่ 19) พบว่าภาพรวมมีความพึงพอใจอยู่ในระดับ **[ระบุระดับ]** ค่าเฉลี่ยเท่ากับ **[X.XX]** ส่วนเบี่ยงเบนมาตรฐานเท่ากับ **[X.XX]** เมื่อพิจารณาเป็นรายด้าน พบว่าด้านที่มีค่าเฉลี่ยสูงสุดคือ **[ระบุด้าน]** (ค่าเฉลี่ย **[X.XX]**) ส่วนด้านที่มีค่าเฉลี่ยต่ำที่สุดคือ **[ระบุด้าน]** (ค่าเฉลี่ย **[X.XX]**) ซึ่งสอดคล้องกับวัตถุประสงค์ข้อที่ 3 ของการวิจัย

## 5.2 อภิปรายผล

ระบบที่พัฒนาขึ้นสามารถแก้ปัญหาที่ระบุไว้ในความเป็นมาของการวิจัย (หัวข้อ 1.1) ได้ตรงประเด็น กล่าวคือ ช่วยให้นักศึกษาติดตามชั่วโมงกิจกรรมสะสมของตนเองได้แบบเรียลไทม์แทนการรอสอบถามหรือตรวจสอบเอกสารกระดาษ ช่วยลดภาระของผู้รับผิดชอบกิจกรรมในการตรวจสอบและสรุปผลด้วยตนเอง และรวมศูนย์การประชาสัมพันธ์กิจกรรมไว้ในที่เดียว สอดคล้องกับแนวทางของ ธนพล แย้มทุ่ง และ อรอุมา พร้าโมต (2568) ที่นำเว็บแอปพลิเคชันมาใช้บริหารจัดการข้อมูลกิจกรรมนักศึกษาแทนกระบวนการแบบเดิมเช่นกัน

ในด้านการยืนยันตัวตนของผู้เข้าร่วมกิจกรรม การใช้ QR Code ที่เปลี่ยนรหัสอัตโนมัติร่วมกับการตรวจสอบตำแหน่ง GPS และการถ่ายภาพเซลฟี ช่วยลดปัญหาการเช็คชื่อแทนกัน ซึ่งสอดคล้องกับแนวทางของ ประเทพ เพชรทองแลง (2561) ที่ใช้ QR Code ตรวจสอบการเข้าชั้นเรียน และ วุฒิพงษ์ ชินศรี และ วิไลลักษณ์ ตรีพืช (2564) ที่ใช้ QR Code บันทึกการเข้าร่วมกิจกรรมผ่านไลน์ออฟฟิเชียลแอคเคาท์ โดยงานวิจัยหลังพบว่าผู้ใช้งานมีความพึงพอใจในภาพรวมระดับดี (ค่าเฉลี่ย 4.58) ซึ่งสอดคล้องกับแนวคิดของระบบที่พัฒนาขึ้นในงานวิจัยนี้ที่ให้นักศึกษาดาวน์โหลดเอกสารสรุปผลกิจกรรมได้ทันทีหลังเช็คชื่อผ่านการอนุมัติ

> **หมายเหตุสำหรับผู้วิจัย:** เมื่อมีผลประเมินจริงแล้ว เพิ่มย่อหน้าที่นี่เปรียบเทียบตัวเลขที่ได้กับ (1) เกณฑ์การแปลผลในหัวข้อ 3.4.2 — ได้ตามที่คาดหรือสูง/ต่ำกว่าที่คาด และ (2) งานวิจัยที่เกี่ยวข้องในบทที่ 2 — เช่น ถ้าค่าเฉลี่ยความพึงพอใจได้ใกล้เคียงกับงานของวุฒิพงษ์ ชินศรี และ วิไลลักษณ์ ตรีพืช (2564) ที่ได้ 4.58 ก็เขียนเปรียบเทียบตรงนี้ได้เลย ไม่ต้องเขียนยาว 1-2 ประโยคเปรียบเทียบก็เพียงพอ

## 5.3 ข้อเสนอแนะ

### 5.3.1 ข้อเสนอแนะในการนำผลการวิจัยไปใช้

1) หน่วยงานที่นำระบบนี้ไปใช้งานจริงควรกำหนดผู้รับผิดชอบดูแลข้อมูลพื้นฐาน (คณะ สาขาวิชา ตำแหน่งเทียบโอนชั่วโมง เกณฑ์การประเมิน) ให้เป็นปัจจุบันอยู่เสมอ เนื่องจากข้อมูลเหล่านี้มีผลโดยตรงต่อการคำนวณชั่วโมงกิจกรรมของนักศึกษาทุกคน

2) ควรประชาสัมพันธ์และอบรมการใช้งานเบื้องต้นแก่นักศึกษาและเจ้าหน้าที่ก่อนเริ่มใช้งานจริงในภาคการศึกษาแรก โดยเฉพาะขั้นตอนการเช็คชื่อด้วย QR Code ร่วมกับ GPS ซึ่งต้องเปิดสิทธิ์เข้าถึงตำแหน่งและกล้องบนอุปกรณ์มือถือ

### 5.3.2 ข้อเสนอแนะสำหรับการวิจัยหรือการพัฒนาในครั้งต่อไป

1) ระบบปัจจุบันรองรับการใช้งานผ่านเว็บเบราว์เซอร์เป็นหลัก ควรพัฒนาแอปพลิเคชันมือถือ (Native Mobile Application) ให้ครบทั้งระบบปฏิบัติการ Android และ iOS เพื่อประสบการณ์ใช้งานที่ดียิ่งขึ้น โดยเฉพาะการแจ้งเตือนและการเข้าถึงกล้อง/GPS

2) ควรเพิ่มระบบแจ้งเตือนผ่านอีเมลด้วยผู้ให้บริการ SMTP จริงของหน่วยงาน แทนการใช้งานในสภาพแวดล้อมทดสอบ เพื่อให้นักศึกษาได้รับอีเมลแจ้งเตือนจริงอย่างสมบูรณ์

3) ควรพิจารณาเพิ่มระบบ "กิจกรรมซ่อมเสริม" สำหรับนักศึกษาที่ใกล้สำเร็จการศึกษาแต่ยังสะสมชั่วโมงไม่ครบเกณฑ์ หากมหาวิทยาลัยมีนโยบายจัดกิจกรรมชดเชยลักษณะนี้ในอนาคต เนื่องจากระบบปัจจุบันมีเพียงการตรวจสอบและแสดงสถานะเท่านั้น ยังไม่มีฟังก์ชันจัดกิจกรรมชดเชยโดยเฉพาะ

4) ควรมีการศึกษาประสิทธิภาพของระบบในสภาวะการใช้งานพร้อมกันจำนวนมาก (Load Testing) เช่น ช่วงเวลาที่มีนักศึกษาสแกน QR Code เช็คชื่อพร้อมกันหลายร้อยคนในเวลาไล่เลี่ยกัน เพื่อประเมินความสามารถในการรองรับของระบบก่อนนำไปใช้งานจริงในวงกว้าง

5) ควรทำการศึกษาวิจัยติดตามผลหลังการใช้งานจริงต่อเนื่องอย่างน้อย 1 ภาคการศึกษา เพื่อประเมินผลกระทบเชิงลึก เช่น อัตราการผ่านเกณฑ์กิจกรรมของนักศึกษาก่อนและหลังใช้ระบบ ซึ่งไม่สามารถวัดได้ในการประเมินประสิทธิภาพและความพึงพอใจระยะสั้นของงานวิจัยนี้
